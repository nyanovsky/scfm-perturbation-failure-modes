Fine-tuning scGPT on the screen leaves the queried response features inside the shuffled-label band, far below its own gene table

Runs 2 and 3 found that when you ask a single-cell foundation model what happens if you change one gene, the answer carries no usable regulatory signal: the response features sat inside the shuffled-label band while the model's static gene-identity table beat co-expression comfortably. The obvious objection is that the models were never trained to answer that question. So we trained one to.

We fine-tuned scGPT on each CRISPRi screen with the recipe scGPT publishes for perturbation prediction, holding out two of run 3's five folds so a fine-tuned model is only ever scored on perturbations it has not seen, and then pushed the fine-tuned checkpoints through run 3's feature swap unchanged. Across the 10 fine-tuned models in two cell lines, every one leaves the response features inside the shuffled-label band; the highest any of them reaches is 0.04563. The same model's static gene table, read through the same translator on the same held-out perturbations, sits at 0.2279 in HepG2 and 0.2318 in Jurkat, at least 5 times higher than any of them, and fine-tuning does not move that either. The paired differences are small and mostly indistinguishable from zero, with 2 exceptions reported below; none of them is a change of the order that would be needed to reach the gene table.

One reading is less clean, and it is a secondary one. Querying the same checkpoints through the model's own perturbation-flag input, rather than through the value substitution runs 2 and 3 use, is noisier: 2 of those 10 readings sit above the band and above that query's own shuffled draws, at 0.05648 and 0.07508, both in Jurkat. They are still three to four times below the gene table, they are not reproduced by the other arms in the same cell line, and that query's draws are wide enough that this is a weak reading rather than a signal. The Controls section gives the draws.

The same thing is visible on the model's own prediction head, with no translator in the path. Its predicted profile correlates with the measured effect at 0.5451 in HepG2 and 0.3447 in Jurkat, which looks like a model that has learned to predict knockdowns. Measure only what the perturbation flag changes, against the model's own unflagged output, and that falls to 0.08179 and 0.001952. Remove the held-out fold's own mean from both sides and it is -0.03381 and 0.019. Of a predicted profile's variance, 0.1202 in HepG2 and 0.05523 in Jurkat survives subtracting the mean prediction, against 0.7444 and 0.8694 for the measurement itself. What fine-tuning installed is close to one profile for every knockdown, so a read-out that asks which gene was knocked down has very little to recover.

The recipe and the five arms

scGPT publishes its perturbation recipe as a notebook, so there is no trainer to import. The model is scGPT's own TransformerGenerator class, unmodified and constructed with the notebook's settings; the training loop and batch sampler around it are restated, because the run also needs the model to be queryable the way runs 2 and 3 query it. Three checks hold the restatement to the original: the masked-MSE loss is compared numerically against scgpt/loss.py at load time, the batch sampler reproduces the upstream one exactly under --upstream-sampling and that variant is scored beside the default, and every setting is checked field by field against the notebook.

All 14 settings the notebook names are the settings this run used. Two of these are easy to get wrong, because the value in TransformerGenerator's signature is not the value the notebook passes: the class defaults to dropout 0.5 and perturbation-pad id 2, and the notebook passes 0 and 0. The recipe follows the notebook. The notebook fixes schedule_gamma and grad_clip inline rather than as a named variable, so those two are compared by reading its training loop: schedule_gamma 0.9, passed inline to StepLR(..., gamma=0.9), not a named variable; grad_clip 1.0, the tutorial clips to 1.0 inline in its training loop.

The prediction is nearly the same for every knockdown

A feature swap can only find signal the model has. Before concluding anything about the features, it is worth asking whether fine-tuning worked on its own terms. So we scored the model's prediction directly, with no translator in the path: run the perturbation forward pass and compare the predicted profile against the measured effect, one correlation per held-out perturbation, through the same reliability weighting and ceiling correction the feature arms use.

The first two columns are the same prediction measured against two different reference points, and the gap between them is the result. Against the measured control profile the fine-tuned model looks like it is predicting knockdowns: the whole predicted profile correlates with the whole measured effect, between 0.3093 and 0.6159 in every arm. Replace that reference with the model's own output for the same cell without the perturbation flag, so that only what the flag changes is left, and the agreement collapses: no arm reaches 0.16 and six of the ten are negative. The first column is therefore mostly a systematic difference between the model's output and the measured control profile, shared across every perturbation, rather than the model responding to the gene it was told about.

The third column settles it. Removing the held-out fold's own mean from both sides leaves only what distinguishes one perturbation from another, and there the agreement is approximately zero in both cell lines. The intervals on that column are wide, so it is a bound rather than a precise zero; the next two paragraphs give the same conclusion from quantities that are not correlations and do not carry that width.

The last column says the same thing with no scoring rule in the path at all, so it does not inherit the width of a correlation interval. For the measured effects, most of a perturbation's variance across genes survives subtracting the average response: knocking down different genes really does do different things. For the fine-tuned model's own prediction almost none of it does. In the primary arm: HepG2 0.1202 against 0.7444 in the measurement, with a median correlation of 0.8984 between the profiles it predicts for two different knockdowns; Jurkat 0.05523 against 0.8694 in the measurement, with a median correlation of 0.8987 between the profiles it predicts for two different knockdowns.

The same contrast appears inside training, on the validation cells the recipe selects on. Over all 235 epochs of all 16 runs, the uncentred agreement never falls below 0.0601, while the centred version stays within 0.08131 of zero throughout. Fine-tuning improves the one and never moves the other.

This matters for how the rest of the page should be read. The response features sitting inside the null band is not the feature swap failing to find something the model has. There is very little gene-specific structure in the prediction for any read-out to recover.

Those reference arms are recomputed independently for every arm. Across the 6 readings per cell line that withhold the same two folds, every recomputation of an arm returns the identical number, which is the reproducibility of the scoring path itself. The two refits withhold different folds, so their recomputations are scored on different perturbations against a different ceiling and are excluded from that comparison; including them would measure the fold difference, not the code.

The shuffled-label band every score above is read against is run 3's pre-registered null, unchanged: the co-expression arm re-scored against shuffled labels, recomputed alongside the arm it judges. Each fine-tuned arm also draws its own shuffled labels; those draws are not folded into the band, because each addition could only widen it, and all 12 of them fall inside it anyway, so the band is not too tight for the arms it is used to judge.

The perturbation-flag query is the exception, and it is worth stating plainly: its own shuffled draws are much wider than the band, reaching 0.1278 in absolute value, and 4 of the 12 arms drawn that way land outside it. That query asks the model for the effect of a flag it was fine-tuned to read, on genes it never saw perturbed, and the resulting feature is noisy enough that shuffled labels alone can produce a large score. Its column in the table above should therefore be read against those draws rather than the band. On that reading 2 of the 10 readings still sit above the widest draw their cell line produced (Jurkat scGPT table, trainable 0.05648; Jurkat ESM2-3B table, frozen 0.07508), so this column is not a clean null result. Limitations

  • This is a bound, not a demonstrated absence. 2 of the 10 paired differences against the frozen arm exclude zero (Jurkat ESM2-3B table, trainable against the frozen arm, 0.0313; HepG2 ESM2-3B table, frozen against the frozen arm, -0.01222), and 32 such differences are computed across all runs and both references. The fold-centred intervals on the direct prediction are wide enough to admit a modest positive effect, and on these two folds co-expression itself is not separated from the shuffled-label band, so an effect of co-expression's size would not be resolved here. What the design supports is that fine-tuning produces no detectable improvement in the queried response features and leaves them far below the gene table.
  • One read-out is not a clean null. Querying the checkpoints through the model's own perturbation-flag input rather than through the value substitution runs 2 and 3 use puts 2 of 10 readings above both the band and that query's own shuffled draws (Jurkat scGPT table, trainable 0.05648; Jurkat ESM2-3B table, frozen 0.07508). That query's draws are wide and uneven across arms, the other arms in the same cell line do not reproduce it, and both readings are three to four times below the gene table, so it is reported as an unexplained noisy reading rather than as evidence either way.
  • One setting of the recipe could not be reproduced: the tutorial's use_fast_transformer=True needs flash-attn 1.x, which will not build against this torch, so scGPT's own fallback attention path was used. Same attention math, different kernel and different exact numerics. Every other setting the notebook names was checked against it and matches.
  • This is one model family and one recipe. It is scGPT's own published perturbation recipe on the screen the question is about, which is the strongest single test available, but a different architecture or a different objective could behave differently.
  • The fine-tuning data is the same screen the evaluation comes from, split by response group. That is the setting the recipe is published for and it is the setting most favourable to installing the signal, so a null here is informative; it does not speak to fine-tuning on a different screen.
  • Two of five folds are scored for the main arms, which resolves a paired difference more coarsely than run 3's five. The cross-fitted variant covers the whole screen and agrees.
  • The translator is fitted leave-one-fold-out across all five folds, so for a given held-out fold it has seen features from folds the fine-tuned model trained on. That is true of run 3's frozen arms as well and is what keeps the two comparable; it means the held-out claim is about the perturbation, not about the translator's independence from the model's training set.
  • The response features are read at run 3's primary anchor. Run 3 swept four anchors on the frozen model and none of them lifted the features out of the band; that sweep was not repeated on every fine-tuned checkpoint.
  • A null is a statement about what these measurements can resolve. The shuffled-label band and the achieved resolution of each paired difference are reported next to every number so the size of an effect that would have been missed is visible.
